__ Development __

- Saving a valid Script event through ItemRack's editor now approves its exact name, trigger, and Lua source. Scripts introduced or changed outside the editor stay disabled until the player enables and accepts them through a warning prompt; unchanged packaged defaults remain privately trusted.
- Added fail-closed registration, dispatch, and logout checks. Rejected or invalid new Script events are removed before they can persist, while rejected changes restore the last approved version disabled.

__ New in 4.45-beta2 - By Bl4ut0 __

- Fixed same-event generation replacement leaving gear from slots that the newer event set no longer owned. Replacement now emits one coalesced plan that restores dropped slots, keeps retained targets stable, and preserves their original lower restoration history.
- Beta publication notes now include the current beta plus every earlier beta from the same version line, while the in-addon changelog keeps each beta separate for clean stable consolidation.

__ New in 4.45-beta1 - By Bl4ut0 __
- This beta is the primary reliability overhaul produced by the v4.24-to-development audit of historical source, packages, GitHub reports, and CurseForge comments. It replaces accumulated event, transaction, queue, cooldown, binding, and button workarounds with explicit ownership/state boundaries and production-Lua regression coverage for live-client beta validation.
- Uses ordered event frames with per-slot restore ownership so shared Ghostwolf/Mounted sets, buried removal, repeated sets, Zone-under-Mounted rebasing, stale generations, and manual gear changes cannot restore over a newer owner.
- Captures legacy event order and restore history before defaults load, backs up ambiguous state instead of guessing, and suspends automatic swaps without rewriting unknown future schemas.
- Routes set, popup, AutoQueue, deferred, empty-slot, and two-hand moves through one serialized, observed transaction with exact identity checks, preflight space validation, bounded retry, and unified cleanup. ItemRack never changes the global Sound_EnableSFX setting.
- Resolves queue owner/list/enabled state atomically and migrates all legacy queue entries with backups, unknown-field preservation, corruption quarantine, and fail-closed gap and future-schema handling.
- Preserves the newest manual set choice or explicit toggle-off over pending automatic or specialization work even when readiness, casting, or locks delay it, and cancels deferred automatic work whose authorizing generation has ended.
- Uses one generation-aware cooldown authority for buttons, popups, queues, and notifications, while coalescing inventory and protected post-combat refresh work.
- Replaces inherited Blizzard action-button templates with ItemRack-owned button templates, keeps slot 20 visual-only, and avoids forcing GameTooltip:Show() from insecure hooks.
- Uses an empty protected carrier for bound sets and one captured set-level request. Protected requests reconcile after combat; ItemRack no longer emits synthetic /equipslot [combat] macros or promises arbitrary in-combat set swaps.
- Replays deferred Script events once with their original arguments and preserves exact-first rune-copy identity across queue, swap, tooltip, and engraving paths.
- Splits stable delivery into a locally installed production candidate and an approved public finalization, with exact committed/tagged-tree packages, verified manifests, and a hard failure when no local client target exists.

__ New in 2.7 - By Yewbacca __

* Created new consolidated patterns for ItemLink/ItemString-to-ItemRackStyleID, ItemRackStyleID-to-BaseID, ItemLink/ItemString-to-BaseID
* Created new functions that use those patterns, and various other new helper functions, in order to consolidate all ItemString-handling in one place
* Replaced all old-style handling of itemIDs (string.gsub/find/match) and made everything use the new functions instead, for more robust handling as well as easy updates in the future
* Replaced GUI drawing code with references to new functions, to get icons and tooltips to work in the GUI
* Updated the GUI code so that it always draws item tooltips using the player's current level, which ensures that mousing over heirlooms in saved sets will actually show their stats for your CURRENT level (the old code set all levels to 0 which made it so the stats were shown incorrectly as level 1)
* Improved the two functions that actually LOCATE the stored equipment set items inside the player's inventory/equipment/bank (whether it's for equipping, or simply displaying a tooltip), by making sure those functions pass the INCOMING ID through the new level updater (UpdateIRString) to ensure all old Item IDs are up to date, thus fixing the bug where leveling up would cause ItemRack to fail strict item search on all saved sets and resort to any-item-with-the-same-baseID; this injection point was chosen because it fixes the problem completely throughout the board, since everything that locates items relies on the item finding functions
* Updated the functions for getting info for an item (GetInfoByID), posting an itemlink to the chatbox when shift clicking an item in ItemRack's GUI (ChatLinkID), and the function for showing an item in a tooltip, so that they all pass the incoming ID through the level updater (UpdateIRString) in order to work with up-to-date information, since it's important that stats are correct whether it's for posting chat links or looking at a tooltip's stats
* Commented and cleaned up terrible code here and there, as I untangled the messy code (minor changes)
